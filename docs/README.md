# SkillSwap

**SkillSwap это учебный командный проект, разработанный 5-й командой 57-й когорты Яндекс Практикума. Представляет собой сервис обмена навыками, в котором пользователь рассказывает, чему может научить и чему хочет научиться, находит подходящие предложения и предлагает обмен.**

## Что реализовано

- Каталог с поиском, фильтрами, сортировкой и подгрузкой карточек
- Страница навыка с информацией об авторе и галереей фотографий
- Регистрация в три шага, вход и выход из приложения
- Профиль пользователя. Редактирование личных данных, пароля и аватара
- Избранное и общий счётчик лайков пользователей
- Предложение обмена и уведомления с отметкой о прочтении

## Технологии

### Фронтенд

- Основа: React, TypeScript, Vite, Redux Toolkit, React Router
- Интерфейс и формы: CSS Modules, Yup, Swiper, React DayPicker, date-fns
- Хранение фотографий: IndexedDB через idb
- Инструменты: Vitest, Testing Library, ESLint, Stylelint, Prettier

### Бэкенд

- Основа: Node.js, TypeScript, Express
- Переменные окружения: dotenv
- Инструменты: tsx, tsc, ESLint, Prettier

## Запуск и работа с проектом

| Команда | Назначение |
| --- | --- |
| `npm install` | Установка зависимостей фронтенда и бэкенда |
| `npm run dev` | Запуск фронтенда для разработки |
| `npm run build` | Проверка TypeScript и сборка фронтенда в `dist` |
| `npm run dev:server` | Запуск бэкенда для разработки |
| `npm run build:server` | Проверка TypeScript и сборка бэкенда в `server/dist` |
| `npm run start:server` | Запуск собранного бэкенда после `npm run build:server` |
| `npm run preview` | Локальный просмотр сборки |
| `npm run lint` | Проверка ESLint и Stylelint |
| `npm run format` | Форматирование проекта через Prettier |
| `npm run test` | Запуск тестов |

Все команды выполняются из корня проекта.

Фронтенд и бэкенд запускаются в отдельных терминалах:

- фронтенд доступен на `http://localhost:5173`
- бэкенд доступен на `http://127.0.0.1:3001`

Бэкенд находится в папке `server`, отдаёт JSON-моки из `server/data` и фотографии из `server/images`.

## Архитектура

Структура проекта основана на Feature-Sliced Design (FSD):

```text
src/
├── app/        # Инициализация, провайдеры, маршруты и общие стили
├── pages/      # Страницы приложения
├── widgets/    # Крупные блоки интерфейса: Header, формы, карточки
├── features/   # Действия пользователя: вход, регистрация, избранное и другие
├── entities/   # Сущности и связанные с ними компоненты
├── shared/     # Общие UI-компоненты, хуки, функции и ресурсы
├── api/        # Загрузка данных из JSON и хранилища браузера
└── store/      # Redux store, слайсы, селекторы и типизированные хуки
```

Redux собран отдельно в `src/store`. Это осознанное отступление от архитектуры FSD, чтобы команде было удобнее работать с общим состоянием. Для доступа к нему используем `useAppDispatch` и `useAppSelector`.

## Сущности и типы данных

Основные данные проекта: **пользователи, навыки, категории и города**. Ниже описаны их поля и связи.

### User — пользователь

Используется при регистрации и входе, в карточках каталога, на странице навыка и в личном кабинете.

- `id: UserId` — уникальный id пользователя
- `email: string` — почта для входа, её можно изменить в профиле
- `password: string` — пароль для локальной моковой авторизации
- `name: string` — имя, которое показывается в Header и карточках
- `avatarUrl: string` — адрес аватара для отображения. Путь к моковой фотографии или временный URL загруженного файла
- `avatarKey?: string` — ключ загруженного аватара в IndexedDB. По нему фото восстанавливается после перезагрузки
- `birthDate: string` — дата рождения в формате `YYYY-MM-DD`. Возраст вычисляется из неё
- `gender: Gender` — пол. Используется в профиле и фильтрах
- `cityId: CityId` — id города из справочника `City`
- `about: string` — текст «О себе» из личного кабинета
- `learningSubcategoryIds: SkillSubcategoryId[]` — id подкатегорий, которым пользователь хочет научиться
- `likesCount: number` — количество лайков. Используется для сортировки по популярности
- `favoriteUserIds: UserId[]` — id пользователей, добавленных этим пользователем в избранное
- `createdAt: string` — дата создания пользователя в формате ISO. Используется для сортировки новых карточек

Предлагаемые пользователем навыки хранятся отдельно в `Skill` и связаны с ним через `authorId`.

### Skill — предлагаемый навык

Описывает, чему пользователь может научить. Используется в каталоге, поиске, фильтрах и на странице навыка.

- `id: SkillId` — уникальный id навыка. Используется в адресе страницы `/skill/:id`
- `authorId: UserId` — id пользователя, который предлагает навык
- `title: string` — название навыка
- `categoryId: SkillCategoryId` — id категории навыка
- `subcategoryId: SkillSubcategoryId` — id подкатегории внутри выбранной категории
- `description: string` — описание предложения
- `imageUrls: string[]` — адреса фотографий для галереи
- `imageKeys?: string[]` — ключи загруженных фотографий в IndexedDB. По ним восстанавливаются адреса фотографий `imageUrls`

### SkillCategory — категория навыков

Группирует подкатегории. Используется в фильтрах, меню категорий и формах регистрации.

- `id: SkillCategoryId` — уникальный id категории
- `name: string` — название категории
- `subcategories: SkillSubcategory[]` — подкатегории, которые относятся к этой категории

### SkillSubcategory — подкатегория навыков

Уточняет направление навыка. Хранится внутри `SkillCategory.subcategories`.

- `id: SkillSubcategoryId` — уникальный id подкатегории. Используется в навыках и интересах пользователя
- `name: string` — название подкатегории

### City — город

Справочник городов для регистрации, редактирования профиля и фильтрации каталога.

- `id: CityId` — уникальный id города. Хранится у пользователя в `cityId`
- `name: string` — название города для отображения

### AuthUser — сохранённая сессия

Используется для восстановления входа после перезагрузки. Полный профиль хранится в `User`.

- `id: string` — id вошедшего пользователя
- `name: string` — имя, записанное при создании сессии
- `email: string` — почта, записанная при создании сессии
- `token: string` — тестовый токен моковой авторизации

### ExchangeNotification — уведомление

Отображается в поповере колокольчика. В текущем сценарии уведомление получает тот, кто сам предложил обмен.

- `id: string` — уникальный id уведомления
- `recipientUserId: string` — id пользователя, которому показывается уведомление
- `skillId: string` — id навыка для перехода по кнопке «Перейти»
- `text: string` — текст уведомления
- `createdAt: string` — дата создания в формате ISO. Показывается как «сегодня», «вчера» или дата
- `isRead: boolean` — прочитано ли уведомление. Влияет на раздел в списке и красную точку на колокольчике

### ProposedExchange — предложенный обмен

Запоминает, что пользователь уже предложил обмен конкретному навыку. Нужен для состояния кнопки "Обмен предложен" и защиты от повторного предложения. Очистка прочитанных уведомлений не удаляет предложенные обмены.

- `userId: string` — id пользователя, который предложил обмен
- `skillId: string` — id навыка, к которому относится предложение

## Состояние Redux

Redux Toolkit используем для общего состояния, которое нужно разным частям приложения.

### usersSlice — пользователи и сессия

Хранит список пользователей и id текущего пользователя. Профиль вошедшего пользователя получаем из `items` по `currentUserId`, отдельную копию профиля в слайсе не храним.

Поля состояния `UsersState`:

- `items: User[]` — все загруженные пользователи, включая зарегистрированных в этом браузере
- `currentUserId: string | null` — id вошедшего пользователя. Значение `null` означает, что открыт гостевой режим
- `token: string | null` — тестовый токен текущей сессии. При выходе сбрасывается в `null`
- `returnPath: string` — адрес возврата после входа или регистрации. По умолчанию `'/'`
- `status: 'idle' | 'loading' | 'succeeded' | 'failed'` — состояние загрузки. Значения обозначают ожидание, загрузку, успешное завершение и ошибку
- `error: string | null` — сообщение об ошибке загрузки. Если ошибки нет, хранится `null`

Действия слайса:

- `loadUsers()` — загружает пользователей из localStorage или JSON-моков, восстанавливает аватары и обновляет `items`, `status` и `error`
- `addUser(user)` — добавляет пользователя после регистрации
- `updateUser(user)` — заменяет пользователя по его id. Принимает полный объект `User`
- `setSession({ userId, token })` — записывает id пользователя и токен после входа или регистрации
- `logout()` — очищает текущую сессию в Redux. Список пользователей остаётся
- `toggleFavoriteUser(userId)` — добавляет или убирает выбранного пользователя из избранного текущего пользователя и меняет счётчик лайков выбранного пользователя
- `setReturnPath(path)` — запоминает страницу, с которой гость был направлен на регистрацию или вход
- `resetReturnPath()` — возвращает адрес возврата к `'/'`

### skillsSlice — навыки

Хранит навыки для каталога и страниц предложений, позволяет добавлять и обновлять их.

Поля состояния `SkillsState`:

- `items: Skill[]` — загруженные навыки, включая созданные при регистрации
- `status: 'idle' | 'loading' | 'succeeded' | 'failed'` — состояние загрузки. Значения обозначают ожидание, загрузку, успешное завершение и ошибку
- `error: string | null` — ошибка загрузки навыков

Действия слайса:

- `loadSkills()` — загружает навыки из localStorage или JSON-моков, восстанавливает фотографии и обновляет состояние загрузки
- `addSkill(skill)` — добавляет новый навык в список
- `updateSkill(skill)` — заменяет навык по его id. Принимает полный объект `Skill`

### registrationSlice — черновик регистрации

Хранит данные трёх шагов до подтверждения регистрации, чтобы передавать их между страницами и показывать в предпросмотре.

Поля состояния `RegistrationState`:

- `credentials` — email и пароль первого шага
- `profile` — личные данные, ключ аватара и интересующие категории и подкатегории второго шага
- `skill` — название, категория, подкатегория, описание и ключи фотографий навыка третьего шага

Действия слайса:

- `setCredentials(data)` — сохраняет email и пароль первого шага
- `setProfile(data)` — сохраняет данные профиля второго шага
- `setSkillDraft(data)` — сохраняет данные навыка третьего шага
- `resetRegistration()` — очищает данные всех трёх шагов после завершения регистрации

Черновик не сохраняется при перезагрузке страницы.

### filterSlice — фильтры каталога

Хранит выбранные фильтры для каталога и избранного. В store подключён под именем `catalogFilters`.

Поля состояния `CatalogFilters`:

- `mode: 'all' | 'teach' | 'learn'` — показывать все карточки, тех, кто может научить, или тех, кто хочет научиться
- `gender: Gender | null` — выбранный пол автора. Значение `null` означает любой
- `cityIds: string[]` — выбранные города
- `skillCategories: CatalogSkillFilter[]` — выбранные категории и подкатегории. У каждого элемента есть `categoryId` и массив `subcategoryIds`

Действия слайса:

- `setMode(mode)` — выбирает режим «Всё», «Могу научить» или «Хочу научиться»
- `setGender(gender)` — выбирает пол автора. Значение `null` сбрасывает выбор
- `toggleCity(cityId)` — добавляет город в фильтр или убирает его при повторном выборе
- `toggleCategory(categoryId)` — добавляет категорию или убирает её вместе с выбранными подкатегориями
- `toggleSubcategory({ categoryId, subcategoryId })` — добавляет или убирает подкатегорию выбранной категории
- `removeFilter(filter)` — удаляет один фильтр по его типу и значению
- `resetFilters()` — сбрасывает все фильтры к начальным значениям

Отбор карточек выполняется отдельно функцией `filterCatalogUsers`.

### notificationsSlice — уведомления и предложения обмена

Хранит уведомления пользователей и уже предложенные обмены для поповера в Header и состояния кнопки на странице навыка.

Поля состояния `NotificationsState`:

- `items: ExchangeNotification[]` — уведомления всех пользователей. Интерфейс показывает только уведомления текущего пользователя
- `proposedExchanges: ProposedExchange[]` — уже предложенные обмены. Используются для состояния кнопки на странице навыка

Действия слайса:

- `addProposedExchange(exchange)` — запоминает предложенный обмен. Повторную запись для того же пользователя и навыка не добавляет
- `addNotification(notification)` — добавляет уведомление в список
- `markAsRead(notificationId)` — отмечает одно уведомление прочитанным
- `markAllAsRead(userId)` — отмечает все уведомления указанного пользователя прочитанными
- `clearReadNotifications(userId)` — удаляет прочитанные уведомления указанного пользователя. Предложенные обмены остаются
- `setNotifications(data)` — записывает уведомления и предложенные обмены, восстановленные из localStorage

### categoriesSlice — категории

Хранит общий справочник категорий и подкатегорий для меню, фильтров и форм.

Поля состояния `CategoriesState`:

- `items: SkillCategory[]` — категории вместе с подкатегориями
- `status: 'idle' | 'loading' | 'succeeded' | 'failed'` — состояние загрузки. Значения обозначают ожидание, загрузку, успешное завершение и ошибку
- `error: string | null` — ошибка загрузки

Действия слайса:

- `loadCategories()` — загружает категории с подкатегориями из JSON-моков и обновляет `items`, `status` и `error`

### citiesSlice — города

Хранит общий справочник городов для фильтров, регистрации и редактирования профиля.

Поля состояния `CitiesState`:

- `items: City[]` — справочник городов
- `status: 'idle' | 'loading' | 'succeeded' | 'failed'` — состояние загрузки. Значения обозначают ожидание, загрузку, успешное завершение и ошибку
- `error: string | null` — ошибка загрузки

Действия слайса:

- `loadCities()` — загружает города из JSON-моков и обновляет `items`, `status` и `error`

## Хранение данных

Данные сохраняются в localStorage, фотографии в IndexedDB через библиотеку idb. 
При запуске приложение восстанавливает их и заполняет Redux. 
Начальные данные загружаются через локальный API из JSON-моков в server/data. Фотографии моков отдаёт бэкенд из server/images.

Сохранённые пользователи и навыки, сессия, избранное, лайки, уведомления и предложенные обмены **сохраняются в localStorage браузера, поэтому не теряются после перезагрузки страницы**. При запуске приложение считывает их из localStorage и восстанавливает в Redux.

Загруженные фотографии хранятся в IndexedDB через библиотеку `idb`. В данных пользователя и навыка сохраняются ключи `avatarKey` и `imageKeys`. При запуске по этим ключам восстанавливаются файлы и создаются временные URL для отображения.

**Незавершённый черновик регистрации хранится только в Redux и сбрасывается при перезагрузке страницы.**

## Регистрация

Регистрация состоит из трёх шагов:

1. Email и пароль
2. Личные данные, аватар и навыки, которым пользователь хочет научиться
3. Предлагаемый навык, его описание и фотографии

Перед завершением открывается предпросмотр предложения. 
После подтверждения создаются пользователь и навык, пользователь автоматически входит в приложение. 
Поля проверяются через Yup. Минимальный возраст 14 лет. Фотографии принимаются в PNG, JPEG и WebP, размером до 2 МБ каждая.
